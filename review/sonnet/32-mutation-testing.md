# 32. Mutation testing (round 3, Sonnet)

Question: does the test suite actually catch bugs? One small deliberate change at a time in the core logic, run the tests that cover that file, record whether anything failed (killed) or everything stayed green (survived), then revert. For every survivor, write a test that kills it and prove it (fails with the mutation, passes without).

## Result

| | count |
|---|---|
| Mutations run | 226 (domain 128, queries 98) |
| Killed by the existing suite | 161 (71%) |
| Survived the existing suite | 65 |
| ...judged equivalent (no observable difference) | 8 |
| ...real gaps, now killed by a new test | 57 |
| Mutation score with the new tests | 218 of 218 non-equivalent (100%) |

Honest reading: the existing suite is strong on the headline numbers (XP amounts, level ladder, 7/30/50/200 badge thresholds, the 30-day window, cycle boundaries, deleted/ended record edges, off-day semantics, cadence parity). Its weak spots were: the consistency window CAP (counted N+1 days and nobody noticed), the Course/validation edges, `healMissingXp` (start-up XP repair: nothing near it tested the amounts, kinds, cycle or counting), `pushedFrom` on pushed occurrences, the cadence-change path through `updateSettings`, XP cycle stamping when a day is re-affirmed, and several "deleted for good / ended / restored" corner paths.

No mutation revealed a bug in the unmutated source. Every survivor was a missing assertion, not wrong behaviour. Source files are untouched (worktree `git status` shows only new test files).

## What was run

- Domain mutations: first the test files that import the mutated file (`occurrence`, `dayState`, `consistency`, `xp`, `achievements`, `cycles`, `retention`, `validation` tests plus the `edge.*` and `monotonicity` suites that touch them); if all passed, the WHOLE `src/domain` suite (14 files, 296 tests) with `--selectProjects domain`.
- Queries mutations: `src/queries/(mutations|moveSemantics|endedAndRetired|recentlyDeleted|edge.logging|edge.numbers|settingsCache)` first; if all passed, also `src/db/__tests__/(recentlyDeleted|retiredDays)` (real SQLite, uses `internal.ts` helpers). `healXp.ts` mutations also got `src/db/__tests__/edge.restarts` (the only existing place `healMissingXp` is run). The slow `src/queries/edge.scale` and `edge.simulation` suites were run only for the first survivors (I02, I10, I13, which survived them too); for later survivors they were skipped for time, so a few "survived" rows might have been killed by them. The new tests kill each of them regardless.
- `X09`/`X10` mutate `XP_IDEAL`/`XP_FALLBACK` in `src/types/progress.ts` (the XP amounts), outside the listed files but where a bug matters most.
- Method: a small script applies one exact-string replacement, runs jest with `--bail=1`, records the first failing test, then `git checkout -- <file>`. Verification of new tests uses the same script limited to the `*.mutation.test.*` files.

## Notes on notable findings

- **Consistency cap off by one (C02, C03).** `denom >= cap` to `denom > cap` made "last 7" and "last 30" count 8 and 31 days. Existing tests only used series of exactly the cap length or shorter. Now pinned with 10-day and 35-day series for per-task and aggregate.
- **`updateSettings` cadence change (M46, M17).** Removing the whole "finalise the in-progress cycle before switching cadence" call from `updateSettings` passed every existing test. The finalise function was tested directly, but never through the settings write that is supposed to call it. A one-day cycle (`>=` boundary) was also untested.
- **`healMissingXp` (H01-H10).** Seven of ten mutations survived even with the real-database `edge.restarts` suite: wrong amount (10 for a fallback), wrong kind, wrong cycle id, wrong count returned, healing only today. New tests run it against fake repos.
- **XP cycle attribution (M08).** A re-affirmed award being re-stamped with the live cycle (instead of its original one) was untested.
- **`pushedFrom` (S16, S17, I10).** The source day a pushed occurrence reports was never asserted in the domain tests (XP is keyed on it).
- **Badges kept on delete (M22, M53).** The "persist earned badges before deleting / deleting for good" calls were not exercised in the case where the badge is not yet saved.
- **Validation (V02-V11).** One-day Course, zero doses, untracked default, Course steps required, one-off Event needs no cadence, a daily habit whose only step skips Sunday, a weekly routine with no ideal step.
- **Hang, not a failed test (Y04).** Changing `startOfWeek` to `startOfMonth` in `currentCycleWindow` makes `cyclesElapsedSince` loop forever (the next window equals the current one) and grow an array. The suite "catches" it only as a hang; I stopped jest by hand. Not a source bug, but there is no loop guard in `cyclesElapsedSince`.
- Equivalent mutants are listed in the table with the reason. M45 and M49 (extra `reconcileOccurrence` calls in undo/snooze) are "no observable difference found", not proven equivalent: I could not construct a state where dropping them changes XP, badges or events.
